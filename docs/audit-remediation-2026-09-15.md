# LensALPR: исправления и границы проверки

Дата: 15 сентября 2026 года. Репозиторий: `omar07ibrahim/lensalpr`.

**Это проверенный пакет частичных исправлений, а не заключение о завершённом аудите всей кодовой базы или отсутствии ошибок.** Полный запрос на исправление всех проблем не закрыт. Основная ветка не изменялась; изменения предложены через Draft PR #1.

База: `0389bc227d8911c141ed6dd530d25316f58b79f0`.
Коммит кода и проверок: `07d8dc0689ce6be008a7ed73ef565083552e28a3`.
Дерево проверенного кода: `79dea1fb40d246df3dfebc07b4da7472fcd4a6a4`.

## 1. Что именно проверено

Полные локальные копии изменяемых существующих исходников сверены с Git blob SHA из инвентаризации аудита. Изменены пять существующих production Kotlin-файлов: ScanSessionService, LensRotationScheduler, YoloDetector, PlateFormats и AlprResults. Добавлен ModelAssetCache. Также изменены AndroidManifest, тесты PlateFormats и режим исполнения gradlew. Добавлены отдельный воспроизводимый host-набор проверок и Android CI.

Перед публикацией из SHA локально проверенных файлов повторно построено дерево GitHub: оно в точности совпало с деревом опубликованного коммита. Поэтому опубликованные исходники и тесты соответствуют проверенной локальной версии, а не пересказу патча.

Это не означает, что каждый файл репозитория прочитан и проверен построчно. Рассмотрены также материалы аудита, конфигурация сборки и отдельные соседние участки pipeline, записи видео и очередей; для них здесь не заявляется полное покрытие или завершённое исправление.

## 2. Как учтён исходный XML

В `lensalpr-unified-full-audit (1).xml` находятся 152 основных пункта LENS и 326 дополнительных SUP: всего 478 записей. Это не число уникальных подтверждённых дефектов. В документе есть повторяющиеся источники и неоднозначные объединения по прежним идентификаторам и сходству текста.

SHA-256 исходного XML: `ea13c84f0916586e30554b06b1f93db3a66c1aaa5ffd60a415fbf1ac1cee0c0c`.

Для девяти основных пунктов ниже внесены изменения в указанной области. Их статус — `patched_scope_pending_integration`, а не безусловное «закрыто». Остальные 143 основных и все 326 дополнительных записей сохраняют статус `not_independently_revalidated`. Совпадение SUP с исправленным LENS не закрывает SUP автоматически.

Полный поэлементный реестр формируется без потери идентификаторов:

```sh
python3 tools/build_audit_ledger.py '/path/to/lensalpr-unified-full-audit (1).xml' audit-ledger.json
```

Генератор проверяет отпечаток XML и количество записей. Он намеренно отказывается переносить этот набор статусов на другой аудит, где идентификаторы могли измениться. Реестр содержит заголовок, исходные атрибуты, приоритет, расположения и отдельный статус выполненной работы для каждой из 478 записей.

Дополнительно YoloDetector отбрасывает нечисловые и бесконечные оценки, классы и координаты до округления и выдачи Detection. Это защищает проверенный путь от NaN и недопустимых прямоугольников.

### Изменения поведения, важные для проверки

При неизвестной стране `EM72O9` теперь сохраняется как наблюдавшийся идентификатор. Исправление в `EM7209` допускается при LV-подсказке либо явном strictLatvia. Это сознательная защита от превращения настоящих иностранных номеров в другие номера; точность и полноту на реальной выборке ещё нужно измерить. Подсказка страны от OCR также может ошибаться.

SessionOptions освобождаются после сессии, а не сразу после её создания. При ошибке session.close параметры сохраняются для повторной попытки. Эта мера не гарантирует восстановление зависшего нативного SDK. Синхронизация close с inference означает, что close может ждать незавершённый inference; остановку приложения и таймауты необходимо дополнительно проверить на устройстве.

В кэше нет небезопасного fallback на перезапись существующего файла при отсутствии атомарного move: ошибка остаётся явной, прежние байты сохраняются.

## 4. Реально выполненные проверки

Запуск: `python3 tools/host-tests/run.py`.

Сравнение с оригиналом: та же команда с `--repo /path/to/original/checkout`. Использовались одинаковые тесты, компилирующие реальные production-файлы двух версий, а не две копии алгоритма внутри теста.

Среда: OpenJDK 21.0.11, Kotlin/JVM 1.9.0. Код возврата исходной версии — 1, исправленной — 0. Отдельно проверены XML манифеста и Git-режим wrapper. Машиночитаемые сведения и SHA находятся в `docs/audit-verification.json`.

Число 36 — количество ранее падавших сценариев, не число уникальных исправленных багов. Три дополнительных JUnit-теста добавлены в штатный PlateFormatsTest, но этот отчёт не приписывает host-прогону выполнение всей Gradle/JUnit-сюиты.

### Что эти тесты не доказывают

Android, CameraX, ONNX Runtime и org.json представлены явно видимыми doubles. Реально исполняются логика production Kotlin, операции файловой системы, хеширование и взаимодействие потоков JVM. JSON double проверяет доступ к объектам; JSON-грамматика не тестируется. Отсутствуют реальные камера, GPS, TTS, NNAPI/XNNPACK, вендорский ALPR SDK и Telegram.

Это не APK-сборка, не запуск приложения на Android и не дорожный тест. Исторические результаты сборки и тестов из XML не выданы за результаты этого прогона.

## 5. CI и условия выпуска

Добавлен workflow для debug/release-сборки, unit-тестов и lintDebug с сохранением отчётов. Первый запуск на начальном CI-коммите остановился в setup-android до компиляции. Workflow затем изменён на использование Android SDK предустановленного Ubuntu 24.04 runner. Актуальное состояние Android-проверки следует смотреть у соответствующего SHA в PR; данный отчёт не объявляет CI зелёным.

В рабочем контейнере отсутствуют Android SDK, Gradle cache и подключённое устройство. Полную Android-проверку здесь заменить host-doubles нельзя. PR остаётся Draft; автоматическое слияние не включено.

Полный реестр сохраняет также пункты, не перечисленные в этой укрупнённой таблице. Оставшиеся 469 записей нельзя считать закрытыми, ложными или уникальными дефектами только на основании их наличия в реестре.

Резервные копии, учётные данные и нативные бинарники не переписывались, не удалялись и не включались в пакет изменений. Отзыв секретов, изменение истории Git и миграция сохранённых пользовательских данных не выполнялись.

**Решение по выпуску:** это набор проверяемых изменений для дальнейшего review, а не готовая «идеальная кодовая база без багов». До release необходимы завершение оставшегося аудита, Android build/test/lint и испытания на целевом устройстве.
